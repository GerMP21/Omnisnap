## First CI run (2026-11-18)

The branch's first run surfaced six defects, all fixed in the same branch:

- `ci.yml`, `e2e-action.yml` and `action/action.yml` had step names containing
  `": "` unquoted; two of the files were not valid YAML and would never have
  run. Every workflow now parses.
- The planted-fixture check flagged the port's own `appearance-*.html` pages;
  the exporter allows `audit-*` and `appearance-*` as port-only fixtures.
- Windows: `testdata/install/**` was CRLF-converted on checkout, turning
  Mozilla's real signature into a hash mismatch; `.gitattributes` pins it.
- Windows: the tar.xz install tests need an MSI fixture on that lane and are
  skipped there; the snap-profile test now sets `USERPROFILE`.
- Linux conformance: the WebKit driver package is `webkitgtk-webdriver` now,
  and Chrome's sandbox crashed on the runner; CI opts out with
  `OMNISNAP_NO_SANDBOX=1` (documented escape hatch, never set by the product).
- macOS runners were unavailable and cost about ten times an Ubuntu job, so
  macOS is out of the CI matrices **for now** (`ci.yml`, `install.yml`,
  `e2e-action.yml`), `safari-smoke.yml` is manual-only, and the Action's
  `macos` input defaults to `labelled` (`never` drops the job). Re-enabling is
  adding `macos-latest` back to the two matrices; Tasks 2/23 stay open.

## WebKit lanes and the cost gates (later on 2026-11-18)

Installing `weston` and `wpewebkit` unblocked the whole WebKit lane:

- **WebKitGTK under a private Weston display.** Three environment switches
  were missing: `GSK_RENDERER=cairo` (GTK4's Vulkan/GL renderer hangs without a
  GPU), `WEBKIT_DISABLE_DMABUF_RENDERER=1` (otherwise MiniBrowser dumps core
  before the first frame), and the Westons are now actually started because
  the package exists. The viewport is exactly 1280×800, client width 1280.
- **WPE WebKit.** `WPEWebDriver` + MiniBrowser `--headless --size=1280x800`
  needs no compositor and honours the size exactly. Font parity comes from a
  `[websettings]` config file (`--config-file`) with the same four families the
  GTK port passes as flags; without it every text width is 5-8% off. The
  portrait is `OMNISNAP_WEBKIT=wpe`, discovery lists it as `wpe`.
- **Conformance** passes for Blink, Gecko, WebKitGTK and WPE. Two Classic
  driver facts surfaced: `Evaluate` now maps a client deadline to
  `ErrTimeout`, and `Capabilities` grew `NavigationErrors` (false for Classic:
  the driver renders its own error page). A hung script wedges WebKitGTK's
  driver, so the harness restarts the browser.
- **Cost gates.** Probes cost 139 ms median (budget 1.5 s). The disk budget
  passes once every browser's `TMPDIR` is its own temp dir (Chrome's singleton
  socket and Firefox's extension staging were surviving the run). The 1.2×
  lane criterion assumes WebKit is the slow lane as it was for the spike; here
  the working lane is fast and the two lanes contend for CPU (25.8 s WebKit,
  10.8-26 s CDP+BiDi, 36 s combined), so the test logs the numbers behind
  `OMNISNAP_COST=1` and Task 25 stays open.
- **Dataset.** The exporter now skips pages whose engines rendered different
  states, uses a mutant's `labels.json` positives, and writes the spike's
  metadata counters. Measured byte-identical to `dataset.mjs` on the same
  findings: 88/88 real rows, 30/30 planted.

## Schema hosting (later on 2026-11-18)

The five JSON Schemas are published at their `$id`s by a Cloudflare Worker
instead of GitHub Pages:

- `wrangler.json` defines the `omnisnap-schemas` Worker, serves `_site` as
  static assets (`run_worker_first`), and owns `omnisnap.org` and
  `www.omnisnap.org` as custom domains.
- `tools/site/build.py` writes each schema at the path in its `$id`
  (`_site/schema/job/1.json`), plus an index and a 404 page.
- `src/worker.js` redirects `www` to the apex and adds CORS/nosniff to the
  schema responses.
- `.github/workflows/deploy.yml` builds and deploys on schema changes to
  `main`; without `CLOUDFLARE_API_TOKEN`/`CLOUDFLARE_ACCOUNT_ID` it warns and
  skips instead of turning `main` red. The operator runbook is local
  (`docs/local/` is ignored).

GitHub Pages (`pages.yml`) was removed: the domain, TLS and routes are declared
in the repo, and there are no A/AAAA records to maintain.

## Decisions made without the owner (please review)

1. **Pure-Go OpenPGP verification** instead of gpg or a new dependency: v4 RSA
   signatures over `SHA512SUMS.asc`, verified against `internal/install/mozilla-key.asc`
   (Mozilla's published KEY, committed). Works on Windows; tested against a real
   Mozilla signature and a test key.
2. **Unpack tools**: Linux uses `xz` + `tar` (standard library has no xz);
   Windows uses `msiexec /a` (administrative extraction, not an install);
   macOS uses `hdiutil` + `cp`. No packer/unpacker dependency.
3. **Windows Job Objects and file version** call kernel32/PowerShell directly:
   `golang.org/x/sys/windows` was not added (CONVENTIONS "Ask first"). Go's
   `syscall` lacks Job Objects; the PE VERSIONINFO fallback runs PowerShell only
   when the registry has no DisplayVersion.
4. **dom-audit `protrudes-parent`** cannot see a parent's border/background (not
   in the capture format, extract.js changes need approval). It requires a
   parent with a real box and a sibling overlap instead.
5. **Native-form pages are not "controls"** in the planted gates (they are
   `KindNative`, scored through `OnlyTags`), matching the spike's gate.
6. **Bot-wall policy on small pages**: fewer than 50 elements marks a page
   `unreachable (bot wall)`. Planted-suite runs must use full capture (the lab
   will); the CLI applies the live-page policy as specified.
7. **`kbDetail` added to summary causes** (additive): the viewer and the PR
   comment can show the explanation and fix without reading `findings.json`.
8. **`--resume` is per capture**, not per page: a resumed job repeats only what
   is missing or failed, satisfying "recaptures nothing already attempted".
9. **Merged bundles have no `host.json`**: the merged `summary.json` carries the
   host list; `host.json` is a per-machine file and has no list form in its
   schema. Revisit if the Action expects one.
10. **Warnings/hints in `--json` mode**: NDJSON has no warning event type, so
    human-facing hints and font warnings are dropped with `--json`. The summary
    carries the font and capture warnings.
11. **Mutation records every mutant** (Task 70): the operator is fixed by the
    seed, so a page and seed always produce the same bug; a mutant that moves
    nothing is kept as a hard negative (`labels.json: effective=false`) instead
    of being replaced. `--require-effective` brings back the rotation for
    training runs that only want visible bugs (3 of 16 were no-ops on the
    planted pages). `meta.mutation.attempts` exists only in that mode.
12. **Fork comments are a reusable workflow** (`on: workflow_call`) called from
    a consumer-side `on: workflow_run` file: GitHub only fires `workflow_run`
    when the file exists on the default branch, and the follow-up may use write
    tokens even when the PR run was read-only
    ([docs](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_run)).
    `report.yml` skips its own comment step for fork heads.
13. **`actions/download-artifact@v8`** for both fresh-run and cross-run
    downloads: the action's README documents v8 with `run-id` + `github-token`
    for a different run
    ([README](https://github.com/actions/download-artifact#download-artifacts-from-other-workflow-runs-or-repositories)).
14. **`--allow-small-pages`** (CLI): the 50-element bot-wall rule is a live-page
    heuristic; planted and test pages are small by design (46-47 nodes), so the
    flag drops the size rule while the timeout and navigation rules stay.
    Without it, `omnisnap <url>` on a planted page writes `failed.json`.

Four choices were taken after the review; three are implemented, one is on hold:

- [SPEC-ground-truth-mutant-policy](../specs/SPEC-ground-truth-mutant-policy.md)
  (implemented): record every mutant by default, keep the retry behind
  `--require-effective`, and join labels by node id (`side` + `nodeId` in
  `findings.json` only, never in `summary.json`).
- [SPEC-capture-webkit-viewport](../specs/SPEC-capture-webkit-viewport.md)
  (on hold, not approved): WebKitGTK cannot be resized (the launch argument
  does not exist, `/window/rect` is ignored, and `--full-screen` on a 1280x800
  Weston output changes nothing), so a capture at another size would be marked
  and its engine skipped for cross-engine causes. The env gates stay as they
  are.
- [SPEC-ci-action-fork-template](../specs/SPEC-ci-action-fork-template.md)
  (implemented): one template under `.github/workflow-templates/`, the guide
  `docs/github-action-fork-comments.md`, and a pointer from
  `action/README.md`.
