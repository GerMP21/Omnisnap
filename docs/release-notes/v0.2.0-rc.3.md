## Omnisnap v0.2.0-rc.3

The candidate for **v0.2.0**, the first stable release. rc.3 is rc.2 plus two fixes found on omnisnap.org's demo report. If this candidate passes, v0.2.0 ships the same code, with only the version strings and the docs changed.

### New in rc.3

- **A browser that paints nothing is a failed capture.** On one macOS runner image, Safari laid every page out but its screenshots held no text and no images, and Omnisnap compared them anyway, which produced false "Drawn differently" causes. Now, when fewer than 10% of a page's visible text boxes (at least 10 of them) have any ink in the screenshot, the capture fails with "the browser painted none of the page's text". It is listed under Not checked as `capture failed`, it produces no causes, and it counts toward exit code 3. The Action and `report.yml` self-tests fail on it, so a release can't publish from such a runner.
- **The report no longer prints `null`.** It appeared in the top-left corner of every screenshot pane, and under the summary table when no engine was skipped.

### Breaking changes (since 0.1.0-rc.7)

- **Selectors follow the DOM.** `:nth-of-type(N)` is now the element's position in the page, hidden siblings included. Before, it counted only the elements Omnisnap captured, so a hidden first card made the second card's selector point at the first. Every selector is valid CSS: ids, classes and tag names are escaped like `CSS.escape()` (Tailwind's `md:w-1/2`, React's `:r1:`). The same element now gets the same selector in every engine, and DOM-audit findings use the same selectors as causes. A selector you recorded from a 0.1.0 candidate may change. Don't merge bundles from a 0.1.0 candidate with bundles from 0.2.0.
- **Elements inside an open shadow root are named by their shadow host.** `document.querySelector` can't reach inside a shadow root, so the selector now selects the host. Before, it could select a different element.
- **At most three browsers run at once.** A job with more engines than that captures them in groups; the baseline is always in the first group. Use `--max-browsers N` on `omnisnap <url>` and `omnisnap run` to change it. The job file is unchanged. For jobs with more than three engines, `--json` progress events come in a different order; their format is the same.

### Fixes and improvements (since 0.1.0-rc.7)

- **Linux:** under memory pressure, the kernel kills Omnisnap's browsers before your other processes.
- **Windows:** a Firefox installed with `omnisnap install firefox` is now found, and `omnisnap uninstall firefox` waits up to a second for a Firefox that is still closing.
- **Interrupts:** Ctrl-C while the baseline browser is starting exits with 4 (internal error or interrupt) instead of 2. Use `--resume` to finish the job.
- **GitHub Action:** it runs up to four browsers at once, so macOS (Chrome, Edge, Firefox, Safari) captures in one group, about 80 s instead of about 100 s.
- **Releases:** the Action and `report.yml` self-tests now run in the release run with the tag, and npm and PyPI publish only after both pass.

### Upgrading

- **GitHub Action:** change the ref to `report.yml@v0.2.0-rc.3` or `action@v0.2.0-rc.3`. Nothing else changes.
- **npm:** `npm i omnisnap@0.2.0-rc.3` (it is also `latest`). A `^0.1.0-rc.7` range won't move by itself.
- **PyPI:** `pip install --pre omnisnap==0.2.0rc3`.
