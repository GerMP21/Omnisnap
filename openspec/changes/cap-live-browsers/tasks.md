## 3. The live-browser cap

- [x] 3.1 Add `--max-browsers N` to `internal/cli/options.go` for `<url>` and `run`: default 3, an integer of 1 or more, anything else exits 1 (usage) before discovery with a message that names the flag and the accepted values. It is not a job field, so `schema/job.schema.json` stays as it is. Verify: `run_test.go` cases for `0`, `-1`, `two` and `2.5` (exit 1, no launch) and for the default and `--max-browsers 8` (accepted).
- [x] 3.2 Turn `runJob` (`internal/cli/run.go`) into the group loop of design decision 2. Launch in job order with the baseline first until N are live; a failed launch is skipped and does not count. Group 1 runs with the baseline and the failure policy. Later groups run with `Baseline: ""` and skip pages group 1 marked unreachable. Each group's browsers are closed, and their trees dead, before the next group launches. Verify: fake-environment tests in `run_test.go` that record launch, close and capture order: five engines with N = 3 give groups [chrome, firefox, webkitgtk] then [edge, brave]; the baseline listed last still launches first; two failing launches among five give one group of three live browsers; the number of live fakes never exceeds N at any launch; a page unreachable in group 1 gets no session in group 2.
- [x] 3.3 The font check per group: keep the baseline's font report from group 1 and compare later groups against it (`internal/cli/fonts.go`). Verify: a fake-environment test where an engine in group 2 resolves a different sans-serif family warns about that engine, naming the baseline.
- [x] 3.4 Page events across groups (design decision 4): one page-start per page before its first capture, one page-done after its last capture in the last group. With one group, the stream is unchanged. Verify: a `run_test.go` case with two pages, five engines and N = 3 counts one start and one done per page with every capture event between them, and the task 1.2 fixture matches a three-engine run event for event (timestamps and durations ignored).
- [x] 3.5 `--resume` per group: `capture.ResumeState` gets the group's engine ids, so an interrupted group-2 run resumes without recapturing group 1. Verify: a `run_test.go` case that stops after group 1, then resumes, captures only group 2's engines.
